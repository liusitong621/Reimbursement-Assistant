# 报销助手_lst

从零开发的本地 Demo，主流程为员工自助查询有效制度，再扩展到经授权查询本人单据状态。Node.js 22+，无第三方运行依赖。

```bash
npm start
```

访问 http://127.0.0.1:3080 。

## 演示流程

1. 首页切换到「乔姐 · 制度维护」，点击「填入合成样例」，保存草稿，再发布此版本。
2. 切换回员工身份，输入「差旅」「住宿」「发票」检索。结果附原文、来源、版本及生效日期；草稿、过期、撤回和未生效版本不进入结果。
3. 可在 http://127.0.0.1:3080/expenses 载入合成票据，生成报销单，提交模拟 OA。
4. 首页员工勾选授权查询本人单据；未核对时返回「业务事实待周敏核对」。
5. 切换到「周敏 · 业务事实核对」，核对模拟单据，再切回员工重新授权查询。另一位员工无法读取这笔单据。

## 责任分工

- 乔姐维护制度：新增版本、发布、撤回，发布时校验日期与同名版本有效期重叠。
- 周敏核对业务事实：核对模拟 OA 单据进度并记录核对人及时间，不替代审批。
- 员工查有效制度：原文关键词检索，不编造报销额度或适用结论。
- 本人状态查询：服务端以会话身份限制单据归属，明确授权后提供已核对状态，支持撤回授权。切换身份或重启服务后授权失效。

## 当前边界

真实制度需要乔姐提供；默认不预装公司规定。合成样例均明确标注。演示角色切换不是生产身份认证，需后续接入企业 SSO 和真实角色授权。

OA 使用 `oa.mjs` 模拟适配器，未连接真实企业系统、未执行真实审批或支付。真实接入需实现认证、表单/附件映射、幂等提交、状态查询和业务事实更新时间。员工不能推进审批结果。

票据支持 PDF、图片、TXT 和 JSON 上传，JSON 自动导入结构化字段。PDF/图片没有 OCR，须手动录入；金额使用整数分，检查重复发票及缺失字段。没有大模型调用或票据真伪查验。

数据保存于被 Git 忽略的 `data/`。仅监听 127.0.0.1，不用于多人生产部署。业务文件全部从零编写。
